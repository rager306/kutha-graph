## Method and evidence rules

1. Code evidence is a `file:line` from the working tree at `2680cd9`. Symbol locations were taken from a `rg` symbol scan of `crates/kutha-runtime/src` and `crates/kutha-common/src` (557 symbol rows, `tmp/gap-register/symbols.txt`), not from prose.
2. Test evidence is a test file plus the `#[test]` function name. All 204 evidence names already recorded in `.kutha/dictionaries/honeycomb.yaml` (167 unique) were resolved: every one exists as a `#[test]` function in a test file. No honeycomb evidence name is missing, and none is a helper.
3. Absence claims are backed by a literal `rg` over `crates/kutha-runtime/src` and `crates/kutha-common/src` with a stated pattern (for example `rg -i 'hnsw|embedding|\bvector\b'`).
4. **Status convention:**
   - `implemented` — the cell's headline decision has code and at least one named test that fails if the behaviour is removed. Residual decisions inside the cell are named in the gap column.
   - `foundation` — code exists, but no test proves the cell's headline claim, or the cell's decision set is only partly present.
   - `absent` — no code implements the cell.
   Deviation, stated explicitly: ADR-092 (naming/license) has no runtime behaviour, so the kill-test rule cannot apply. It is marked `implemented` on verified file content (`LICENSE`, `Cargo.toml`, `pyproject.toml`) with that caveat in the gap column.
5. Time box: the audit was run inside the ~25 minute budget; no cargo build or test execution was performed (contract forbids cargo). Test names are therefore evidence of *existence and intent*, not of a green run in this session. Where a name alone does not prove the claim, the row says `foundation`, not `implemented`.

## Part 5 — Scope limits of this register

- No test was executed (no cargo per contract). `implemented` means the named test exists, is `#[test]`-annotated, and asserts the behaviour described; it does not mean the suite was run green in this session.
- Statuses describe the headline decision of each cell. A cell marked `implemented` can still contain unimplemented decisions, listed in its gap.
- The register deliberately does not promote, demote or retag any ADR. It also does not re-derive the honeycomb `delivery`/`capability` fields; discrepancies between those fields and this register are recorded as findings, not fixed (fixing them would be a `.kutha/` write).
- Not audited: `scripts/kutha_gov` internals beyond the check ids named, `.cursor/gsd-core`, `tools/`, benchmarks, and the `verus/` proofs. Charts and numbers from `CHANGELOG.md`/`.planning/` were not used as evidence.
