# Claim-honesty audit — v1.60–v1.69 (M166–M176)

Read-only audit of ten closed GSD milestones: v1.60 operational honesty (M166),
v1.61 legal PIT probe (M167), v1.62 performance truth (M168), v1.63 as_of regression
(M169), v1.64 ingest regression (M171, with harness-only M170), v1.65 B3 benchmark
decision (M172), v1.66 M003a GPML parser (M173), v1.67 Gate GB (M174), v1.68 C4
path-policy foundation (M175), v1.69 C1 pack-lifecycle foundation (M176).

No tracked file was edited, no commit/tag/push, no `graph index`, no cargo, no
`kutha-gov` run. The only file written is this report. Numeric claims were checked
against the retained benchmark/test logs under gitignored `tmp/` (still present:
396 entries), against the committed tables in `docs/architecture/benchmark-baseline.md`,
and — for the two CI claims — against the GitHub API with `gh`. Commit ids were
checked with `git show --stat`; test counts by summing `test result: ok N passed`
lines and by counting `#[test]` functions; verification duplication by normalised
string similarity.

Independence is assessed structurally (`read_only_inputs`, body similarity, commit
authorship), not by re-running a verifier model; test behaviour is assessed from the
source, not by executing cargo.

**Verdict.** Most behavioural and numeric claims hold exactly: every bench number in
v1.60, v1.62, v1.63, v1.64/M170–M171 and v1.69 matches a surviving log digit for digit,
every cited commit exists and contains what the text says, and every named test exists
with the advertised count. Two claims do not hold:

1. **v1.68's "distinct `SecurityError::QueryRejected`" was never implemented.** The
   variant exists and is formatted, but nothing constructs it; post-policy engine errors
   are still mapped to `PolicyDenied`. The claim appears in two CHANGELOG bullets and in
   both v1.68 verification files.
2. **v1.69's independent verification files were rewritten after the close** to describe
   stronger tests than the verifier saw (schema 4→5, workspace 762→763, a non-vacuous
   checkpoint test). The PASS attribution was left unchanged and no fresh verify pass is
   recorded, contrary to the explicit re-verify rule.
