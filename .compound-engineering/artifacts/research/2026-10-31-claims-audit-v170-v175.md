# Claim-honesty audit — v1.70–v1.75 (M177–M182)

Read-only audit of six closed GSD milestones: v1.70 C1b pack manifest and operator
registry (M177), v1.71 C5 enrichment foundation (M178), v1.72 Gate GC toy-pack probe
(M179), v1.73 replay-side meta revalidation (M180), v1.74 eCFR edition ambiguity
(M181), v1.75 meta-surface threat audit (M182). Same method as the v1.76–v1.79 audit:
every numeric claim traced to a surviving artifact or marked unverifiable, every named
test checked for existence and for asserting the claimed behaviour, and every
"found and fixed" checked for the code or test change it implies.

No tracked file was edited, no commit/tag/push, no `graph index`, no cargo, no
`kutha-gov` run. The only file written is this report.

**Verdict.** The behavioural claims of v1.70, v1.71, v1.72 and v1.75 are supported by
code and tests. Two things are not:

1. **v1.73's verification says a vacuity finding was fixed; it was not.** The two
   enrichment tests it names still fail on the empty-source check and never reach the
   check they are named for (`m180_replay_meta.rs:164`, `:190`). Two rejection paths
   (unknown pack, duplicate cache key) are therefore untested at HEAD, and the claim
   propagates into the phase summaries, `.planning/MILESTONES.md` and `CHANGELOG.md`.
2. **v1.74's central falsifiability claim is backwards.** The new edition-count assert
   is logically implied by the two equality asserts that precede it, so it cannot fail
   independently. A reader who trusts "the count assert uniquely catches a lost edition"
   would believe the milestone added a guard it did not add.

Neither is a product defect: both are documentation/verification claims that overstate
what the tests prove. The gate claims themselves are corroborated by the harness
observation log.

Highest-value fix, one line: give `enrichment_for_unknown_pack_fails_replay` and
`duplicate_enrichment_cache_key_fails_replay` a real source event and assert the error
reason, exactly as `enrichment_wrong_version_and_retired_pack_fail_replay` already does.

## Verified consistent (no action)

- **Named tests exist and are the claimed shape.** Static count of `#[test]` fns:
  `m177_pack_manifest` 10, `m177_pack_registry` 5, `m178_enrichment` 10,
  `m179_gate_gc` 2, `m180_replay_meta` 10 + the unit test
  `tail_proposal_after_checkpoint_must_cite_visible_source`
  (`provenance.rs:435-436`), `m182_meta_threats` 10, `m167_ecfr_pit` 1 — every advertised
  count matches. Every function named in prose exists with that exact name.
- **Gate GC's AS OF claims.** `m179_gate_gc.rs:80-84` asserts `AS OF 2015` →
  `50-kmh` and `AS OF 2020` → `30-kmh`; the boundary is real because the second assert
  is `valid_from = 2020` with `valid_to = Some(2020)` on the first (`:37`), i.e. half-open
  `[from, to)`. The same two cuts are re-asserted after retire (`:99-100`) and after
  reopen (`:113-114`).
- **v1.72 zero production edits.** `git diff --stat 5ed1ffa..4d0dc3b -- crates/*/src
  Cargo.toml Cargo.lock build.rs .kutha/dictionaries` is empty; `56ee712` adds only the
  test, `docs/architecture/gate-gc.md`, and bookkeeping. `aa82389` changes 8 lines of the
  test plus wording, matching "fixed in wording, not code".
- **Scope honesty in Gate GC.** `docs/architecture/gate-gc.md:29` and the test docstring
  (`:5-10`) say plainly that the query path never consults pack state, so the probe
  evidences neutrality, not query sufficiency. No document claims more.
- **Manifest identity is checked at emit, admission and replay.** Emit:
  `pipeline.rs:702-737` (`validate_shape` → `validate_identity` → store blob → install).
  Admission: `admission.rs:160-177` → `pack_manifest.rs:189-216`. Replay:
  `provenance.rs:132-141` → same function. `load_manifest` (`pack_manifest.rs:165-183`)
  recomputes the raw SHA-256 before parsing.
- **Enrichment is a fold no-op.** `event.rs:330` gives `EnrichmentProposal` empty
  `object_ids`; `fold.rs:1073-1076` matches it to `{}`. No relation field exists on the
  op, so no Horn eligibility.
- **Validation runs before the payload append.** `pipeline.rs:643-674` validates the
  proposal with the pending payload, then appends `StoreBlob`, then the proposal;
  `m178_enrichment.rs:129-153` asserts the log length is unchanged after a rejection.
- **One state machine, one proposal check.** `PackLifecycleTracker` is used by admission
  (`admission.rs:249`) and replay (`provenance.rs:101`); `check_proposal` is called from
  admission (`admission.rs:144`), replay (`provenance.rs:174`) and the emit pre-check
  (`pipeline.rs:656`). Retired names are released in both gates
  (`lifecycle.replay` and `operators.retire` in `provenance.rs:119-125`).
- **"Found and fixed" in v1.75 has both code and test.** `9976d04` adds the single-pass
  tracker and `replay_meta_is_not_quadratic`; `d1c8697` fixes retired-name release and
  `admission_accepted_log_reopens_after_retire` (`m182_meta_threats.rs:263-276`) guards it.
- **v1.74 did not touch fixture text.** `git log -- 'crates/kutha-runtime/tests/fixtures/ecfr/*.txt'`
  shows only the original `d843d81`; `dd2747a` and `a273326` touch the README, the test and
  the doc only.
- **Gate claims are corroborated by the harness observation log** (`.kutha/events.jsonl`,

  105-check `harness.run` with `high = 0`, `low = 0`, `status = ok`, `cargo = ok` occurs

## Limits

- `tmp/` is gitignored scratch (277 MB present). The M182 timing figures and the eCFR
  raw XML are gone; nothing in this report reconstructs them.
- `.kutha/events.jsonl` is gitignored. A fresh clone has no gate evidence at all.
- Test counts are static (`#[test]` attributes). I did not and could not verify that any
  test passes without running cargo.
- I did not evaluate whether the tested behaviour is the right behaviour, only whether
  the recorded claims match the repository.
