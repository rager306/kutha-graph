STCA: как мы строим графовый движок

Spatiotemporal Compositional Architecture — это не слоган, а каркас: пространство (изолированные доменные модули) × время (журнал событий → граф) × композиция (плагины как «предметы» с бюджетом). Kutha — реализация STCA на Rust плюс быстрые картины графа и словари для агентов. Продуктовый якорь: корневой STRATEGY.md. Стек ADR: 001 видение → 002 STCA → 000 locks → соты 010+.

Продукт · боль (из ADR-000 + логов 2026-08-15)

Какую проблему решаем

Нужен графовый движок, в котором одновременно:

  1. Агенты и GenAI живут внутри runtime, а не как надстройка над storage.
  2. Время и аудит — first-class: bi-temporal, lineage, point-in-time, fork.
  3. Производительность multi-hop / vector / analytics — класса Samyama / FalkorDB.
  4. Расширяемость — плагины с обратимыми эффектами, без переписывания ядра.

Классика не закрывает набор: state-first БД быстры, но слабы на агентах/истории/fork; чистый event-sourced граф аудитируем, но теряет multi-hop; memory-frameworks (Graphiti/Zep) — не СУБД и зависят от внешнего графа; document + in-DB GenAI — слабый native graph.

White space (сессия): in-DB agents + event projections + bi-temporal + reversible hot views + portable cognitive packs — в одном Rust-движке. Квадрант: high temporal × high hybrid × in-DB agents. Исследовательские дыры рядом: write-time contradiction contracts, provenance×time, LLM вне trust boundary для temporal operators (не «ещё больше RAG»). См. STRATEGY.md · Target problem; artifacts/research/patterns.md.

Продукт · персоны / GTM

Для кого (клин, не клетка)

Primary Legal / нормативные temporal-агенты: assert / invalidate / AS OF с replayable lineage; LLM не юридический авторитет.
Secondary сейчас Scientific / scholarly archive (revision-scoped evidence) — sibling pack на той же физике (ADR-093).
Лестница дальше Regulated finance → horizontal agent runtime → enterprise KG + security. Меняются словари/packs, не runtime.

Enterprise must-have до «корабля»: ABAC / temporal policies, agent sandbox, multi-tenancy, immutable audit, CMK / air-gap — после доказанной физики ядра. Fit (research): regulated ~9/10; hybrid ~8–9/10; чистая замена Samyama ~5–6/10 — гипотезы, не маркетинг.

Продукт · инвестиции простыми словами

Куда кладём усилия

  1. Сделать время честным — лог, fold, bi-temporal, один такт emit→cascade→idle с квитанцией.
  2. Сделать граф достаточно быстрым — скорость = съёмные картины того же лога (CSR…), не вторая БД; сначала одна hot-проекция.
  3. Сделать модули и вертикали втыкаемыми — порты + packs (legal / science / …).
  4. Сделать агентов управляемыми и проверяемыми — словари + meta-prompt; тесты = replay/fork; sandbox до enterprise.

Это те же четыре tracks в STRATEGY.md, без жаргона осей. Оси STCA (Space / Time / Composition / Verify) — как читают инженеры; tracks — как читает продукт.

Продукт · метрики (честный статус)

Что измеряем — и чего ещё нет

Пока нет PRD. Ниже — кандидаты-фальсификаторы из ADR-000 R9 / exit criteria, не продуктовые KPI go-to-market. Их нужно пересмотреть в PRD.

  • Replay integrity — расхождение strict replay на golden logs → 0.
  • Cascade / quantum bound — глубина и wall time такта под бюджетом.
  • Legal PIT probe — корректность (и позже latency) norm@date.
  • Hot-path proximity — multi-hop vs Samyama/FalkorDB-класс; цель «близко», не всегда обогнать.
  • Fork cost — время/место fork-and-diff на фиксированной нагрузке.

Следующий шаг продукта: PRD, который зафиксирует north-star и leading/lagging метрики для wedge (legal). Strategy намеренно не притворяется, что KPI уже известны.

Уровень 2 · два контура

Пространство и время

Пространство Домен режется по функциям (заказ, норма, агент…), а не по папкам «controllers / services / repos». Снаружи модуля видны только порты (интерфейсы). Внутри — свой маленький гексагон.
Время Правда не в «текущей таблице». Правда в ленте событий. Граф — это пересчёт ленты слева направо. Можно проиграть заново и получить то же; можно ответвиться (fork) и сравнить.
Связка Плагин/pack регистрируется в общем контексте. Эффекты должны уметь откатываться. Глобальное поведение — не один гигантский workflow, а сборка локальных функций.

Уровень 2 · композиция

Зачем «рюкзак» Cui в архитектуре

Каждый модуль — как предмет: при выделении ресурса \(v\) (время CPU, глубина cascade, токены агента) даёт локальный выигрыш \(h_i(v)\). Система выбирает раскладку бюджетов через max-свёртку — без жёстко прошитого сценария «сначала всегда шаг 1, потом 2».

  1. Есть общий бюджет \(V\) (например лимит cascade на один такт).
  2. Каждый pack объявляет, что умеет при доле бюджета.
  3. Свёртка даёт лучшую допустимую комбинацию — или явный отказ с квитанцией «бюджет исчерпан».
Формула (для инженера)

\(H_{\mathrm{next}}[W]=\max_{0\le v\le W}\{h_i(v)+H[W-v]\}\) — лекция 8 Tianyi Cui, «Nine Lectures on the Knapsack Problem». В Kutha это мост к идеям cascade budgets и конкуренции материализаторов.

Уровень 2 · продукт

Чем Kutha дополняет «чистый» ActiveGraph

Чистый событийный граф силён в истории и детерминизме, но слаб в «быстром мире» (многопрыжковые обходы, векторы). State-first СУБД — наоборот. Kutha стоит на STCA и добавляет:

  1. Быстрые картины (CSR, HNSW…) как съёмные проекции над тем же логом — не второй источник правды.
  2. Словари и meta-prompt — агенты внутри движка, нейросеть не единственный судья.
  3. Время фактов — семантика «как у Graphiti» (сроки, закрытие устаревшего), реализованная своим кодом.
  4. Самодостаточность — ядро на RocksDB + in-process модули; чужие графовые БД и облачные API не обязательны для assert / invalidate / «на дату».

Глубина STCA · как графовая СУБД

Оптимальность, скорость MVP, тесты

Манифест STCA задаёт физику. Продукт Kutha ещё должен доказать себя как graph DB:

  1. Оптимальность / производительность — hot path (CSR / sparse / GraphBLAS-like) и join-стратегии (кандидат: Leapfrog Triejoin / WCOJ-класс) оценивать по output/bound, не по «ещё один Cypher». AS OF + multi-hop — отдельная cost model (R3/R6).
  2. Скорость до MVP — P0 = один heartbeat (log+fold+cascade+replay), не полный honeycomb. Одна reversible CSR-проекция раньше зоопарка индексов.
  3. Стратегия тестирования — Strict Replay + Fork-and-Diff как default (дешёвый аудит); sociable in-memory ports; content-addressed cache внешних LLM/tool; Regimes held-out — опция для agent seams, не блокер P0.

Антипаттерны производительности (D8): replay tax без snapshots; single-writer без WAL batching; fat events. Без них «надёжный event-sourcing на больших логах мёртв» (лог сессии 2026-08-15).

Такт runtime (emit → стабилизация)

Событие попадает в лог → граф обновляется fold’ом → behaviors и relation behaviors предлагают патчи → снова в лог — пока очередь не пуста или бюджет cascade не исчерпан. Итог такта — квитанция.

Уровень 3 · инженерия

Границы в Rust и как проверяем

  1. Workspace: common (Event, Patch) · modules/* (вертикальные срезы) · app-shell (единственный composition root).
  2. Законы: домен не знает БД; наружу только ports; инфраструктура подключается в shell.
  3. Strict Replay: тот же лог → тот же граф; внешние ответы из content-addressed кэша.
  4. Fork-and-Diff: ветка с другого правила с середины истории → сравнение графов.
  5. Regimes (опционально для агент-паков): правка промпта/кода только через гейты, held-out падение = discard.

Эталонный каркас ActiveRuntime и полный текст законов — в docs/architecture/stca-guide.md.

Словарь

Расшифровки

STCA — Spatiotemporal Compositional Architecture: пространство × время × свёртка плагинов.

SoT — source of truth, источник истины (у нас — event log).

Fold / foldl — последовательное применение событий к пустому графу.

Behavior / Relation Behavior — реакция на событие или на тип ребра; выдаёт патчи/новые события.

Port / Adapter — порт = интерфейс домена; адаптер = реализация снаружи (БД, HTTP) — в ядре Kutha часто не обязателен.

Vertical slice — модуль «по фиче», а не по техническому слою.

Max-convolution (Cui) — способ собрать глобальный оптимум из локальных функций бюджета.

Materialization — быстрая картина для запросов; пересобираема из лога.

ADR / D1–D10 / R1–R10 / P0–P3 — решения, открытые вопросы и этапы бэклога в ADR-000.
