# Phase 53 Context: Commit marker (COMMIT-01)

**Milestone:** v0.12 / harness M002 S05
**Requirements:** COMMIT-01
**Depends on:** Phase 52 (Persister append; shipped)
**Source:** `.compound-engineering/artifacts/research/2026-10-03-commit-01-internal-analysis.md` and `2026-10-03-commit-marker-prior-art.md` (both recommend option A). The owner approved proceeding with the recommended option on 2026-10-04 ("корректируй ... через GSD auto" after the recommendation was shown).
**Run rules:** `docs/process/gsd-auto-contract.md` (RED first; oracle preservation; bench gate; CBM primary, GitNexus secondary outside M013)

## Decision

**A: `Op::QuantumOutcome` stays the commit marker of a User quantum.** On open, an uncommitted suffix is not visible. No WAL or jsonl format change, no writer change, no environment switch (option D rejected: two encodings double the oracle surface and hide a bad writer behind the other mode). Commit frame (B) and quantum envelope (C) are revisited in S06 only if segments need them.

## Locked decisions

- **D-01 (scope):** `crates/kutha-runtime/src/store.rs` (or a new `src/commit.rs`), tests, ADR Evidence. No change to `pipeline.rs`, `wal.rs` frame layout, `Event`, `Op`, fold, or the writer path. `hydrate.rs`/`provenance.rs` only if unavoidable; record it as a deviation.
- **D-02 (classifier):** one function `op_commit_class(&Op) -> CommitClass { SelfCommit, NeedsOutcome }` with an EXHAUSTIVE `match` on `Op` (no `_` arm), so adding an `Op` variant breaks the build until it is classified. `NeedsOutcome`: product `Assert`/`Retract`/`Correct`/`CorrectInterval`/`Behavior` (derive the exact variant names from `kutha-common`). `SelfCommit`: `Define`, `TtAnchor`, `StoreBlob`, `JustificationCite`, `QuantumOutcome`, and dictionary asserts in the reserved `kutha:*` namespace (they are emitted in `ReceiptMode::Dictionary`, which writes no outcome). Verify each class against `ReceiptMode` use in `pipeline.rs`.
- **D-03 (committed prefix):** `fn committed_prefix(events: Vec<Event>) -> Vec<Event>`. Let `i` be the index of the last `QuantumOutcome`. Everything up to and including `i` is kept. After `i`, keep events in order until the first `NeedsOutcome` op; drop that op and everything after it. No `QuantumOutcome` anywhere (genesis only logs): keep events up to the first `NeedsOutcome` op (a log with product ops and no outcome at all is an uncommitted quantum). Self-commit ops (Define, TtAnchor, StoreBlob, cites, dictionary asserts) in the tail before the first `NeedsOutcome` op survive, which preserves the Phase 52 intern-only and TtAnchor appends.
- **D-04 (where):** `store::open` applies `committed_prefix` right after `load_events_d04` and BEFORE sidecar loading, `from_snapshot`/`hydrate_from_log`, and `replay_check`. A snapshot whose `log_offset` counts fold ops beyond the committed prefix is a log that is behind the snapshot: fail closed with `InvalidData` (not silent).
- **D-05 (observability):** `open` stays read-only. Add `store::open_report(dir) -> io::Result<(Runtime, OpenReport)>` or an equivalent `#[doc(hidden)]` accessor where `OpenReport { dropped_uncommitted: usize }` tells how many events were hidden. `store::open` keeps its signature and delegates.
- **D-06 (heal for append):** `Persister::attach` keeps failing closed on a dirty disk tail. Add `store::open_for_append(dir) -> io::Result<(Runtime, Persister)>`: if `dropped_uncommitted > 0` it first runs a full atomic `persist` of the trimmed runtime (Phase 50 path) so the files equal the committed prefix, then attaches; otherwise attaches directly. A failpoint-covered crash during the heal reopens to the same committed prefix.
- **D-07 (oracles, RED first)**, in `crates/kutha-runtime/tests/m002_commit01.rs`: `payload_without_outcome_is_not_visible` (append with partial last quantum: payload lines and frames written, outcome line/frame missing, via a failpoint after N-1 events; reopen hides it, fold equals the previous committed state); `complete_quantum_with_outcome_is_visible`; `intern_only_suffix_survives`; `tt_anchor_only_suffix_survives`; `typed_justification_pair_survives`; `genesis_and_dictionary_asserts_survive_without_outcome`; `product_assert_without_any_outcome_is_hidden`; `snapshot_ahead_of_committed_prefix_fails_closed`; `open_report_counts_dropped`; `open_for_append_heals_then_appends`; `heal_crash_matrix_reopens_to_committed_prefix`; `every_op_variant_is_classified` (compile-level: exhaustive match; plus a test enumerating variants if feasible); `retract_correct_user_quanta_follow_the_same_rule`; `horn_followon_quantum_is_atomic` (payload+follow-ons+outcome; cutting inside it hides all of it). Keep all existing M010-M017, m002_snap01 and m002_append01 oracles unchanged.
- **D-08 (kill-mutations the verifier will run):** naive drop-after-last-QO (must fail the intern-only/TtAnchor oracles); keep product Assert without QO; apply the trim after hydrate instead of before; classify a product op as SelfCommit; skip the heal; count QO in `log_offset`.
- **D-09 (docs, same phase):** ADR-010 and ADR-014 get a dated 2026-10-04 Evidence line recording COMMIT-01 = option A, the self-commit set, and that B/C wait for S06; ADR-012/060 one-line pointers. `semantic-gap-review.md` status for the crash-between-payload-and-outcome gap. `honeycomb.yaml` restage line. Statuses stay **Proposed**. Residual recorded: Typed/Dictionary multi-event groups have no outcome by design, so a crash inside such a group can still expose a partial group (only `Define`-level atomicity is guaranteed). CHANGELOG entry in the last commit.
- **D-10 (bench):** writer unchanged; `open` gains one linear walk. Re-run `ingest_plain.n`, `as_of.n` interleaved base vs head, 4 pairs, medians, separate worktrees with separate absolute `CARGO_TARGET_DIR`s, binaries run from their own worktree's `crates/kutha-runtime`; remove worktrees and target dirs afterwards (`git worktree list` must show only the main tree). Also record `open.n` before and after. Over 10 percent on medians is a stop.
- **D-11 (roles):** verifier is not the executor; the controller owns STATE, the README lease row and the CHANGELOG lease entry; no `53-VERIFICATION.md` from the executor.
