## Locked decisions

- **D-01 (cell and status):** new honeycomb ADR `docs/ADR/ADR-023-test-strategy-and-oracle-matrix.md`, Status **Proposed**, sits with 020–022 conventions; register it in `docs/ADR/README.md` and `.kutha/dictionaries/honeycomb.yaml` (cell 023: `map` lifecycle only, `capability: none`, evidence lists only real governor/test names). It records decisions, not a promise: it does not authorise features, does not accept itself, and does not rewrite D1–D10.
- **D-02 (ADR content, evidence-based):** (a) *Oracle taxonomy*: decision oracle (pins a decided behaviour; changing it needs a decision), characterization oracle (pins current behaviour; labelled so; may be replaced when the owner decides), property/differential oracle (seeded, no new dependency), crash/failpoint oracle, kill-test (verifier-authored), governor oracle (dictionary check), bench gate. (b) *Layering rules*: every durability invariant needs a named test and a named kill-mutation that fails it; a `cfg(feature)` test needs an FSM observe row (Phase 57 `observe_rocks` is the template); owner-gated invariants are `blocked: decision` rows, never `#[ignore]`/xfail and never a green placeholder; a characterization test must say so in its name or doc comment. (c) *Determinism rules*: seeded LCG only (`m017_determinism.rs` pattern), EventIds are not stable (UUID v7), compare derived triples not ids until the owner decides identity; no wall-clock or sleep in oracles. (d) *Mutation policy*: the verifier runs a mutation list per slice (D-08 in each CONTEXT); record the list in the matrix; `cargo-mutants` or similar is allowed as a verifier/controller tool only if already installed on the host (`cargo mutants --version`); it is never a repository dependency and never a gate. (e) *Options considered with a one-paragraph verdict each* (use search MCPs, `jina`/`exa`, cite 3–6 sources in a research note, not in the ADR body): property-based testing, mutation testing, deterministic simulation testing (TigerBeetle VOPR, FoundationDB style), crash-consistency testing (ALICE / CrashMonkey style), differential testing, model-based testing, approval/snapshot tests. Verdict must say what fits this repo (single crate pair, no new deps, research stage) and what is deferred.
- **D-03 (matrix, machine-readable first):** `docs/architecture/test-matrix.yaml` is the source of truth (rows: `id`, `plane` product|harness, `invariant`, `layer`, `oracle` (list of test fn names or governor check ids), `kill_mutation` (short text or `none`), `status` one of `killed`, `characterization`, `gap`, `blocked`, `spec-only`, `gate` (`default` | `feature:<name>` + the FSM observe row id | `controller`), `owner` (slice id like `M019-S05`, or a decision id like `C01`, `HORN-KC-01`, `ASOF-ELIG-01`, `TR-02`, `DET-02`), `source` (audit section or ADR id)). `docs/architecture/test-matrix.md` is a short human page (how to read, status counts, the gap list by slice, the blocked list by decision) and must not duplicate rows by hand. Seed from the audit: M002 durability (atomic sidecar, dir fsync, committed prefix, tail guard, chain verify, manifest flip, torn active tail, sealed truncate, missing active, migrate, export_jsonl, Rocks rebuild, two-writer open, mixed Typed/Dictionary group, migrate × tail guard, active at exact frame end, wrong-role active in manifest), semantic core (FF5 AS OF, FF6 allowlist, claim/support identity, Correct/CorrectInterval, Horn at TT=MAX vs `as_known_on`, derived identity, cascade order, CSR vs fold differential, seeded determinism, replay_check provenance, legal TR-02 force-vs-publication), harness (freeze rules, ledger, artifact-budget, selftest classification, parallel parity). Every `gap` row names the M019 slice that will close it (S05 durability A, S06 durability B, S07 semantic expansion) or `unowned` (then it needs an owner decision recorded in the matrix page). Count rows honestly; do not mark `killed` unless the test exists and a mutation is recorded.
- **D-04 (governor row, existing kinds):** one new check (YAML) proves (i) every test fn named in `oracle` exists (reuse `rust_test_asserts`/`yaml_map_list` machinery; harness check ids must exist in `checks.yaml`), (ii) every `blocked` row has a decision owner from the allowed list and no matching `#[ignore]` exists in `crates/**/tests`, (iii) every `gap` row has a slice owner that exists in `.kutha/ROADMAP.md` or `unowned` is rejected, (iv) every `feature:` gate names an existing observe row in `fsm.yaml`, (v) status `killed` requires a non-`none` `kill_mutation`. Selftest must prove the check by its own rule (Phase 57 classification: derived or explicit mutation, not file deletion). A new kind is allowed only if `yaml_map_list` cannot express (iii)–(v); justify it in the intake doc. Do not add the matrix to `observe_cargo.required`.
- **D-05 (do not overclaim):** the matrix is a map of oracles, not a coverage number; governor green on the matrix check means "named oracles exist and statuses are internally consistent", not "the product is tested". State this in ADR-023 and the matrix page.
- **D-06 (scope fence):** no edit under `crates/`, `.kutha/STATE.md`, README lease row, `.planning/STATE.md`, state.json, ROADMAP ticks. No changes to named M010–M017 oracles. The research note goes to `.compound-engineering/artifacts/research/2026-10-05-test-strategy-prior-art.md`.
- **D-07 (roles and verification):** executor commits per theme with named files, one SUMMARY ≤60 lines. Independent verifier (no CONTEXT/PLAN/SUMMARY): checks ADR-023 is Proposed and registered; matrix rows parse; every named oracle fn really exists (and reports any that exist only under another name); 10 sampled `killed` rows are real (the named test exists and a mutation in a scratch copy fails it, at least 5 run for real); every `gap`/`blocked` row is justified against the audit; seeded mutations of the matrix (rename an oracle, mark `killed` with `none`, `blocked` with an `#[ignore]` added in a scratch crate copy, unknown owner, feature gate without observe row) are each caught by the new check with a HIGH; `uv run kutha-gov py`, `precommit`, `ci`, `selftest` green; precommit/ci stay fast.
