## Locked decisions

- **D-01 (what is parallel):** (a) `run_checks`: independent checks run in a pool; (b) `run_selftest`: each check's proof (copy, mutate, run) runs in its own scratch directory in the pool; (c) `observe_cargo` / `observe_rocks` may overlap `run_checks` + `run_selftest` because they only read the live tree and use the real target dir while selftest uses scratch trees; (d) emit, tenant and fold stay serial and run last, in canonical order. The FSM in `.kutha/dictionaries/fsm.yaml` stays the dictionary of phases; add only data the executor needs (for example an `overlap_with:` / `parallel: true` hint per phase) — no new Python class; use existing kinds where possible.
- **D-02 (determinism = the oracle):** `--jobs 1` is the serial reference. With any N ≥ 2 the findings (id, severity, message, order), the exit code and the emitted JSONL rows (ignoring only timing fields such as `phase_ms`, timestamps and run ids) are byte-equal to `--jobs 1`. Results are merged in dictionary check order, never completion order. Pytest first: parity test on (i) the real tree, (ii) a mini tree with several seeded failures (HIGH and LOW in different checks), (iii) a mini tree where one worker raises.
- **D-03 (fail closed):** a worker exception, a pool breakage or a timeout becomes a HIGH finding for that check (`worker-error`, with the check id and the exception text), never a silent skip and never a missing row; a crashed pool falls back to serial for the unfinished checks, and the fallback is itself reported as a LOW finding. No `except Exception: pass`.
- **D-04 (configuration):** `--jobs N` on `ci`, `selftest`, `precommit` and the env var `KUTHA_GOV_JOBS`; precedence flag > env > default; default `min(os.cpu_count(), 8)`; `0` or an invalid value is rejected with a clear error, `1` means serial. Document in `docs/process/governor-intake.md` and `AGENTS.md` Commands is **not** required (keep AGENTS.md untouched); put the usage in the intake doc and the `--help` text.
- **D-05 (pool kind):** processes (`concurrent.futures.ProcessPoolExecutor` with the `spawn` or `forkserver` context; no `fork` after threads) for CPU-bound check evaluation and scratch copies; a thread only for the overlapped cargo subprocess if simpler. Checks are YAML dicts, so they pickle. No new dependency. Python 3.13 only (`uv`).
- **D-06 (scratch isolation):** every proof uses a unique scratch directory under repo-local `tmp/` (`tempfile.mkdtemp(dir=...)`), removed in `finally`; no shared mutable global (index caches added in Phase 57 are per process and keyed by root, verify there is no cross-worker or cross-root leak); no two workers write the same path; `.kutha/events.jsonl` is written only by the parent.
- **D-07 (selftest copy size):** the scratch copy skips `.compound-engineering` and `.planning/milestones`, plus anything else not read by any check. Prove it with the serial oracle: run the full selftest serial before and after the skip list; classification counts and results are identical (58 derived / 4 explicit / 2 skipped at Phase 57) and no check needs a skipped directory (if one does, keep exactly the files it reads and say so).
- **D-08 (measurement, honest):** record wall time for `ci`, `selftest`, `run_checks` and `precommit` with `--jobs 1`, `2`, `4`, default (12 CPUs on this host), three runs each, warm cache, in the SUMMARY. The Phase 57 baseline is ci ≈ 56 s (the earlier 9 min baseline is obsolete after the index cache). Goal: default jobs at least 40 percent faster than `--jobs 1` on `ci`, or an honest explanation (for example cargo dominates). A cold-cache `ci` (after `cargo clean -p kutha-runtime` or a fresh `CARGO_TARGET_DIR` under `tmp/`) is measured once and reported. Do not trade correctness for speed.
- **D-09 (pytest):** the hermetic stubbed `test_ci_green_on_this_tree` stays; add parity and failure tests from D-02/D-03; if pytest total time can drop with test-level parallelism through the stdlib only, do it; otherwise do nothing (no `pytest-xdist` unless it is already a dev dependency).
- **D-10 (non-goals):** no new checks, no weaker checks, no change to severities; no theatre-check deletion (S04 decides with the matrix); no crate edits; no change to `.kutha/STATE.md` semantics.
- **D-11 (verifier, independent):** runs `ci`, `selftest` and `precommit` at jobs 1, 4 and default and diffs findings and JSONL rows (modulo timing); kill-mutations: seed a failing check in a scratch copy and require the same HIGH at every jobs value; make a worker raise (monkeypatch in a scratch copy) and require a `worker-error` HIGH, not green; run two parallel `ci` invocations on separate scratch copies and require no interference; mutate completion order (add a sleep to the first check in a scratch copy) and require unchanged ordered output; check no leftover `tmp/` scratch directories and no leftover processes after a run and after a forced worker error.

## Out of scope

Test strategy and matrix (S04), merging duplicate rows, rewriting checks, product code, cloud/remote execution.
