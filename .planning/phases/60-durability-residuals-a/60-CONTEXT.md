## Locked decisions

- **D-01 (scope):** close the 13 matrix gap rows owned by `M019-S05` (`DUR-checkpoint-omitted-qo`, `DUR-jsonl-inode-rename`, `DUR-seg-manifest-sync-all`, `DUR-seg-final-sync-dir`, `DUR-mixed-typed-dict`, `DUR-migrate-tail-guard`, `DUR-active-exact-frame-end`, `DUR-wrong-role-active`, `DUR-two-writer`, `DUR-chain-active-prev`, `DUR-manifest-pre-rename`, `DUR-sealed-trailer-lie`, `DUR-migrate-concurrent`). Each row ends `killed` with a recorded `kill_mutation` and a real test, or stays `gap`/becomes `spec-only` with a written reason in the matrix. A new oracle that is RED on current code is a real bug: fix it in the same task and say so; a new oracle that is green on current code is a pinned guarantee and must still be shown to fail under its named mutation (scratch copy). Do not mark `killed` without running the mutation.
- **D-02 (WRITER-01, single-writer advisory lock):** std `File::try_lock` (stable on 1.99) on a lock file inside the store dir (`kutha.lock`; decide the name and document it). Taken by every writer entry point: `Persister::attach` / `open_for_append`, `store::persist` (full rewrite), `store::migrate`, `store::export_jsonl` when it writes inside the store dir. Held for the life of the writer, released on drop (also on panic/unwind). A second writer fails closed with a distinct `io::ErrorKind` (document which; `WouldBlock` is the natural one) and a message that names the lock file; no writes happen before the lock is held. Readers (`store::open`) take no lock and keep working while a writer holds it (atomic renames make that safe; prove with a test). A stale lock file left by a crashed process must not block (advisory locks die with the process: prove with a test that spawns a child process that locks, is killed, and a second writer then succeeds). The lock file must not break existing directory-content assertions (for example the 7-dir-fsync and no-tmp-files oracles, migrate/export listings): adjust only by excluding the lock file by name, recorded in the SUMMARY as a mechanical edit; any other assertion change stops the phase.
- **D-03 (GROUP-01, Typed/Dictionary multi-event group vs `committed_prefix`):** problem: after the last `QuantumOutcome`, `committed_prefix` keeps self-commit ops until the first NeedsOutcome op; Typed/Dictionary multi-event groups carry no outcome, so a crash can expose a partial group. FIRST TASK (before code): a design note `.compound-engineering/artifacts/research/2026-10-05-group-commit-design.md` (≤100 lines) with at least three options (for example: (a) every group is written inside one frame batch plus one sync and recovery treats a torn batch as absent via a group-length header in the frame stream, no Event/Op schema change; (b) a trailing group marker op; (c) leave as documented residual), with their failure modes, format impact and oracle design, and a verdict. HARD STOP: if the chosen option needs a change to `Event`, `Op`, `Snapshot` or the segment frame format, STOP after the note and report to the controller (ADR-000 D-locks and named oracles are involved); do not implement it. If option (a)-style recovery is possible without a format change, or the verdict is (c) with an explicit oracle that pins today's behaviour as `characterization`, proceed. Whatever is chosen, record it in ADR-010 and ADR-014 (dated Evidence line + F11/residual wording), update the matrix row, and keep ADRs Proposed.
- **D-04 (oracle list and mutations):** per row the executor writes the test in `crates/kutha-runtime/tests/m019_dur_a.rs` (new file; reuse failpoints and seams from `m002_seg01.rs` / `m002_append01.rs`; no new dependency; no sleep; no wall clock) and records the kill mutation. Required mutations: skip `sync_all` on the tmp manifest before rename; drop the final `sync_dir`; in-place write of `events.jsonl` (inode witness); truncate the active segment at an exact frame end (must keep the prefix, distinct from a torn frame); manifest `active` naming a sealed file; flip the active header prev-hash; crash after the new active header exists but before the manifest rename; sealed trailer `bytes` rewritten to match a truncated payload; tail guard after `migrate` (same-length last-frame swap); lock skipped in `attach`; lock held by a dead process; `persist` racing `migrate` on a legacy dir (the lock must serialize or fail closed, never interleave).
- **D-05 (named oracles):** FF5, FF6, M010–M017, `m002_*` assertions do not change. Allowed mechanical edits: directory-listing helpers that must ignore the lock file. Any other change stops the phase.
- **D-06 (docs):** ADR-010/014 (and ADR-012 if the lock touches snapshot text) get dated 2026-10-05 Evidence lines: single-writer lock shipped (what it is: advisory, per directory, local filesystem only; NOT multi-process coordination across hosts, NFS caveats), the group decision, residuals still open (no external chain anchor; `open` O(N); `Persister` not wired into `kutha-tenant`). Update the matrix rows and counts, `docs/architecture/test-matrix.md`. CHANGELOG Product entry in the last commit. ADR statuses stay Proposed.
- **D-07 (graph and bench):** Phase start: CBM `list_projects`/`index_status`/`check_index_coverage` on touched paths and GitNexus `list_repos`; if stale the controller reindexes (tell the controller; executors never run `index_repository` or `gitnexus analyze`). Blast radius with CBM `trace_path` + GitNexus `impact` on `Persister::attach`, `store::persist`, `store::migrate`, `store::export_jsonl`, `store::open_for_append*`; `rg` arbiter; record counts. Bench: `ingest_plain.n`, `as_of.n`, `open.n` base (tag-free HEAD at lease) vs head, 2 interleaved pairs, separate worktrees with separate absolute target dirs, run from the worktree's `crates/kutha-runtime`; clean up worktrees and target dirs afterwards (`git worktree list` must show only the main tree). Over 10 percent on medians is a stop (host noise is about 15 percent between back-to-back runs: use interleaved medians).
- **D-08 (roles and verification):** executor commits per task, named files, one SUMMARY ≤60 lines. Independent verifier (no CONTEXT/PLAN/SUMMARY) re-runs each required mutation of D-04 in scratch copies (fresh `CARGO_TARGET_DIR` per copy), checks the lock semantics (second writer, dead-process lock, reader unaffected, panic releases, lock file ignored by listings), checks the matrix rows moved only with a real test, checks ADR statuses, runs `cargo test --workspace --offline`, `kutha-gov py/precommit/ci/selftest`, and the pytest suite.
