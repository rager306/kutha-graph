## Locked decisions

- **D-01 (what changes, what does not):** the event LOG stays the source of truth (ADR-000 D1 unchanged); only its physical encoding moves from `events.jsonl` + covering `events.wal` to a manifest plus sealed segments plus one active segment. `events.jsonl` becomes a derived, on-demand export. Dated Evidence lines only (2026-10-04); no silent rewrite of D1-D10 or D010-*; honeycomb stays **Proposed**. The owner's M002 plan (`.kutha/ROADMAP.md` S06) already states "the jsonl export is no longer the SoT"; the closing report must flag this wording change to the owner.
- **D-02 (format):** magic `KUTHASEG` + u32 v1; frames identical to `wal::frame_bytes` (len_le32, crc32, JSON `Event`); sealed files end with one trailer frame (JSON `{"k":"seal","n","first","last","bytes","chain"}`, CRC'd, not part of the chain). `KUTHAWAL` v1 is untouched.
- **D-03 (chain):** `H0 = [0;32]`, `H = SHA256(H || frame_bytes)` per event frame; tip stored in trailer and manifest. Use the `sha2` already in the workspace; NO new dependency, no Cargo.toml edit unless the dependency is missing from `kutha-runtime` (then add only `sha2` already pinned elsewhere in Cargo.lock and say so).
- **D-04 (manifest):** `manifest.json` `{"v":1,"sealed":[{name,first,last,count,bytes,chain}],"active":"seg-NNNNNNNN.log"}` replaced via `replace_via_tmp` + `sync_dir`. Names `seg-{seq:08}.log`. Unnamed `seg-*.log` files are ignored (crash leftovers).
- **D-05 (recovery):** a present manifest selects the segmented path and `events.jsonl`/`events.wal` are never read (manifest wins, no fail-closed on a disagreeing jsonl). Sealed segments are fully verified on open (magic, trailer, count/first/last/bytes/chain, stitching); lazy skipping is forbidden. Active: drop a torn last frame; seal trailer on a still-named-active file ends the stream. Flip, swap, reorder, delete or truncate in a sealed file, manifest/file disagreement, missing active: `InvalidData`. Non-`InvalidData` I/O errors propagate. After the load: `committed_prefix`, then hydrate/replay_check (unchanged).
- **D-06 (writer):** after sub-slice 54b, an empty or migrated directory is written as segments; a legacy directory keeps writing jsonl + WAL until `store::migrate(dir)` (explicit; never inside `persist`). `Persister` on a segmented dir appends frames to the active segment with exactly ONE `sync_data` per quantum, no jsonl write, O(1) tail guard on the active file only. Rollover constants `SEGMENT_MAX_BYTES = 64 MiB`, `SEGMENT_MAX_EVENTS = 65536` with a thread-local test seam; seal order: trailer + sync_data, new segment header + sync_data, atomic manifest flip + dir fsync. Checkpoint refreshes snapshot + sidecars only (never regenerates jsonl).
- **D-07 (migrate and export):** `store::migrate(dir)` loads via the legacy path, writes segments + manifest atomically, verifies by reopening (ids equal), then leaves `events.jsonl` in place as an export and removes `events.wal`. `store::export_jsonl(dir)` writes jsonl from the segmented log on demand. The harness's own `.kutha/events.jsonl` is a different thing and is untouched.
- **D-08 (rocks spike):** `rocks_spike.rs` keeps indexing jsonl offsets; re-pointing to (segment, offset) is S07.
- **D-09 (sub-slices, three plans in this phase):** 54-01 = format + manifest + `open` (persist still legacy); 54-02 = Persister + rollover + default writer + heal; 54-03 = tamper oracles + migrate + export + docs. Each plan is RED first, committed separately, with its own bench numbers in `docs/architecture/benchmark-baseline.md` (ingest_plain.n and as_of.n unchanged paths; `open.n` and `persist_append.n` recorded; over 10 percent on medians for ingest/as_of, or an `open.n` rise over 10 percent versus the previous plan, is a stop). Interleaved base-vs-head pairs, separate worktrees and separate absolute target dirs, remove worktrees afterwards.
- **D-10 (oracles):** `crates/kutha-runtime/tests/m002_seg01.rs` (names in the design note section 5, plus: `manifest_wins_over_disagreeing_jsonl`, `unnamed_segment_leftover_ignored`, `rollover_crash_matrix_reopens_to_prefix`, `seal_trailer_on_named_active_ends_stream`, `legacy_dir_still_opens_and_appends_as_before`, `migrate_preserves_ids_and_fold_fingerprint`, `append_after_migrate_resumes`, `export_jsonl_roundtrips_and_is_never_read_on_open`). All existing M010-M017, m002_snap01/append01/commit01 oracles stay unchanged and green on the legacy layout; where a test inspects jsonl tails of a freshly written default dir, pin it to a legacy dir via a test helper (record each as a mechanical edit), never weaken an assertion.
- **D-11 (docs):** ADR-000 Clarification pointer, ADR-010/012/060 Evidence (2026-10-04), `docs/architecture/p0-spike-inventory.md`, `.kutha/ROADMAP.md` S06 text is the controller's, `.planning/REQUIREMENTS.md` DOC-06 wording is the controller's; governor claim text (`m012a-s04-verify-persist`, `B-m012a-s04`) stays as a legacy oracle with a clarifying message; `honeycomb.yaml` restage line; CHANGELOG entry per plan.
- **D-12 (roles):** verifier is not the executor; the controller owns STATE, README lease row, CHANGELOG lease entry; no `54-VERIFICATION.md` from an executor.
