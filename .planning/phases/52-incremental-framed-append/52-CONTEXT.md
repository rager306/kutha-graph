# Phase 52 Context: Incremental framed append

**Milestone:** v0.12 / harness M002 S04
**Requirements:** APPEND-01, PERF-GATE
**Depends on:** Phase 50 (atomic sidecars, log-ahead open, fail-closed WAL; shipped)
**Source:** `docs/architecture/m002-cloud-kernel-io-intake.md`, ADR-010/012 Evidence (2026-10-03), Phase 50 `m002_snap01.rs`
**Run rules:** `docs/process/gsd-auto-contract.md` (RED first; oracle preservation; bench gate; CBM primary, GitNexus secondary outside M013)

## Locked decisions

- **D-01 (scope):** `crates/kutha-runtime/src/{store,wal}.rs` (a new `src/persist_append.rs` is allowed if `store.rs` would pass 700 lines), `benches/baseline.rs` (one new metric) and tests. No segments, manifest, hash chain (S06), no commit-frame or `Op::QuantumOutcome` change (S05), no RocksDB use, no event or WAL format change (WAL magic and version stay), no change to `Runtime`, fold or hydrate APIs.
- **D-02 (API):** the existing `store::persist(&Runtime, dir)` stays as the full atomic rewrite and keeps all its oracles. New `store::Persister` (`attach(&Runtime, dir)` after a full persist or open, `append(&mut self, &Runtime)`, `checkpoint(&mut self, &Runtime)`, `close(self, &Runtime)`). It remembers `durable_count`, the jsonl byte length, the WAL byte length and the last durable `EventId`.
- **D-03 (append quantum):** `append` writes only events beyond `durable_count`: JSONL lines (`write_all`, no sync) then WAL frames (same length+CRC32 frame), then exactly one `sync_data` on the WAL file. That `sync_data` is the commit point: events acknowledged by `Ok` are never lost; events of an interrupted `append` may or may not survive (at-least-recovered), never half. Prefix bytes of `events.jsonl` and `events.wal` are not rewritten or truncated. `append` with nothing new does no I/O and no sync.
- **D-04 (tail guard, O(1)):** before writing, `append` checks that both file lengths equal the remembered lengths and that the last record of each file decodes to the remembered last `EventId` (seek from the end, read one record). Any mismatch, or `rt` log shorter than `durable_count` or whose event at `durable_count - 1` has another id, returns `InvalidData` and writes nothing. The caller recovers with a full `persist`. The guard never scans the whole log.
- **D-05 (torn tails):** `recover_events` already drops a torn last WAL frame. For `events.jsonl`, a final line without its terminating `\n` is a torn tail: it is dropped by `read_jsonl_events`; a complete (newline-terminated) malformed line still fails `InvalidData`; all old jsonl oracles keep their assertions. `load_events_d04` keeps `ids_cover` selection (longer valid prefix wins when one covers the other); if the WAL is shorter than jsonl because the WAL tail was torn, the jsonl events are used (unacknowledged tail survives).
- **D-06 (checkpoint):** `checkpoint` is the Phase 50 atomic path for the lease files: `sync_data` of jsonl, then snapshot, `terms.jsonl`, `quantum_outcomes.jsonl`, `justifications.jsonl` via `replace_via_tmp` plus dir fsync. It runs automatically inside `append` when `events_since_checkpoint >= CHECKPOINT_EVERY` (a `pub const`, 4096) and in `close`. Between checkpoints the snapshot and sidecars are stale: Phase 50 rules apply on open (log ahead of snapshot is tail-folded; stale-prefix sidecars are absent and rebuilt from the log). `checkpoint` never rewrites the log files.
- **D-07 (data-sync count):** add a `#[doc(hidden)]` thread-local counter of `sync_data`/`sync_all` calls on log files (like the Phase 50 dir-fsync counter) so a test can assert exactly one log-file sync per non-checkpoint `append` quantum.
- **D-08 (failpoints):** extend the Phase 50 seam idea to `append`: stop after jsonl write, after WAL write (before sync), after WAL sync, and at each checkpoint step. For every stop, reopening yields the previous state A or the next state B (or `InvalidData`), `replay_check` passes, and no acknowledged event is missing.
- **D-09 (oracles, RED first)**, in `crates/kutha-runtime/tests/m002_append01.rs`: `append_keeps_prefix_bytes_of_jsonl_and_wal`; `append_one_log_sync_per_quantum`; `append_nothing_new_does_no_io`; `append_torn_wal_tail_drops_only_tail`; `append_torn_jsonl_tail_without_newline_is_dropped`; `complete_malformed_jsonl_line_still_fails`; `append_replay_parity_with_full_persist` (same events: fold fingerprint, `as_of`, `replay_check` equal to a store written by full `persist`); `append_tail_guard_mismatch_fails_closed_without_writing`; `append_crash_matrix_reopens_to_prefix`; `open_between_checkpoints_uses_stale_leases`; `checkpoint_every_threshold_refreshes_snapshot`; `append_after_open_resumes` (open then attach then append).
- **D-10 (bench, PERF-GATE):** add `persist_append.n` to `benches/baseline.rs` (after `persist.n`, append 1 percent more events to the same dir via `Persister`) and record next to `persist.n` full rewrite. `ingest_plain.n` and `as_of.n` are compared base vs head interleaved, 4 pairs, medians (host noise is about 15 percent; back-to-back single runs are not evidence). Over 10 percent on medians is a stop. Record numbers in `docs/architecture/benchmark-baseline.md`.
- **D-11 (docs, same phase):** ADR-010/012/014/060 Evidence lines (2026-10-03; statuses stay Proposed); `semantic-gap-review.md` status for the O(N) persist defect; the "O(N) persist" defect lines in ADR-010/012 are marked closed for the append path; `honeycomb.yaml` restage line; CHANGELOG entry (product and process apart) in the last commit.
- **D-12 (residual to record):** between checkpoints the WAL duplicates the jsonl (S06 segments remove that); `append` is not multi-process safe (single writer; no lock file in this slice); acknowledged-vs-unacknowledged semantics are about `append`'s `Ok`, not about the quantum-outcome sidecar (COMMIT-01, S05).
- **D-13 (roles):** verifier is not the executor; the controller owns STATE, the README lease row and the CHANGELOG lease entry; no `52-VERIFICATION.md` from the executor.

## Out of scope

Sealed segments, manifest, hash chain, multi-writer locking, commit frame, vacuum, RocksDB wiring, any Runtime or fold change.
