## Locked decisions

- **D-01 (ROCK-02, index staleness beyond the tip):** today `SegmentIndex::open_or_rebuild` compares only `m:tip` (sealed chain tip, count, last EventId); a poisoned or bit-rotted locator in the middle of the index survives until `get_event` re-verifies the frame. FIRST TASK: a short design note `.compound-engineering/artifacts/research/2026-10-05-rocks-staleness-design.md` (≤80 lines) comparing at least: (a) per-sealed-segment binding (store each sealed segment's chain hash/count from the manifest in `m:` keys and compare the whole sealed list on open — detects any change of a sealed segment, O(#segments)); (b) an index digest maintained at build/catch_up and verified by a key scan on open (O(N) keys, no log IO) behind an explicit `verify_full()`; (c) RocksDB paranoid checks only. Choose (a) as the always-on check and (b) as an explicit opt-in `verify_full()` unless the note shows a reason not to. Poisoning the index value of an existing locator while `m:tip` matches must be detected by `verify_full()` and by `get_event` (already `InvalidData`); `open_or_rebuild` must rebuild when the sealed list differs from the manifest. RED first. The index stays a droppable lease: it never becomes a source of truth, never stores payloads (Phase 55 `rocks_values_hold_no_payload` stays green). No format change of the log or segments. A change to the Rocks key/meta layout bumps `m:v` (old layout → rebuild, never read).
- **D-02 (export race):** `export_jsonl` now takes the writer lock (Phase 60). Add the oracle for `DUR-export-race`: `export_jsonl` while a `Persister` holds the lock fails closed (`WouldBlock`) and writes nothing; after the writer drops, the export equals the log; an export never reads a half-appended frame (take the lock before reading). Mutation: export without the lock.
- **D-03 (MEM-01, `bytes_per_fact`):** the benchmark reports `bytes_per_fact` 17218 B (before Phase 50) vs 25200 B (after). Hypothesis from the audit: `persist_until` builds `encoded_log` (clone of every event + `stable_define` per dict string) and `wal::frame_bytes` copies, and `Runtime::snapshot` clones `GraphFold`; peak RSS includes these transient copies. Measure, do not guess: a counting `GlobalAlloc` wrapper (allocated bytes, peak live bytes, allocation count) in a scratch bench/example under `tmp/` or in a `#[cfg(test)]`/`examples/` file that adds NO dependency to `Cargo.toml` (dhat/heaptrack only in a scratch copy if installed). Produce a table: live bytes after ingest, peak during `persist`, peak during `open`, per phase of `persist_until`. Fix only what is cheap and behaviour-neutral (for example drop `encoded_log` before the snapshot clone, stream frames instead of building a second full copy, avoid cloning `GraphFold` for the snapshot if a borrow works), each with RED→GREEN where an oracle can express it (an allocation-count or peak-live-bytes test with a generous threshold is allowed only if deterministic; otherwise record the bench number). If the rise is inherent (transient copies during persist), say so with the measurement and leave the code. Bench gate applies: `ingest_plain.n`, `as_of.n`, `open.n` within 10 percent on interleaved medians (6 pairs, discard warm-up, pinned core, separate worktrees with absolute target dirs; host noise ~15 percent).
- **D-04 (CLEAN-01):** delete `hydrate::log_has_quantum_outcome` and the `#[allow(dead_code)]` on `wal::append_events` only if `rg` and CBM/GitNexus show no caller (including tests and benches); otherwise keep and record why. `rocks_spike.rs` and `m002_rock00.rs` stay (named oracles; matrix rows) — record the decision and the relation to `rocks_index` in ADR-010/012 Evidence: spike indexes legacy jsonl offsets, `rocks_index` indexes segments; both optional features; neither wired. No other deletions. Public re-exports and `pub mod` surface: no change.
- **D-05 (wiring decision, record only):** record in ADR-010 Evidence (dated 2026-10-05): `SegmentIndex` and `Persister` are not wired into `Runtime`/`kutha-tenant`, with the reasons (no consumer needs O(1) event lookup yet; `Runtime` keeps its in-memory maps; wiring would add a second source of derived state and the Rocks build cost, ~5.5 min cold) and the trigger that would reopen it (a read path that must locate events without hydrating the log). No code wiring in this slice.
- **D-06 (matrix and docs):** rows `DUR-export-race`, `DUR-rocks-mid-stale`, `DUR-bytes-per-fact` become `killed` / `characterization` / `spec-only` with real oracle names and recorded mutations, or stay `gap` with a reason; `docs/architecture/test-matrix.md` counts updated; the `test-matrix` governor check stays green; add an FSM observe row only if a new `cfg(feature)` test file needs it (ADR-023 layering rule: the existing `observe_rocks` row runs `m002_rock01`/`m002_rock00`; add the new rocks tests there or to a new file listed in that row). ADR-010/012 dated Evidence; statuses stay Proposed. CHANGELOG Product entry in the last commit; bench section appended to `docs/architecture/benchmark-baseline.md` by the executor (numbers from interleaved runs only).
- **D-07 (named oracles):** FF5, FF6, M010–M017, `m002_*`, `m019_dur_a` assertions do not change. Mechanical edits only (helper renames). Any other change stops the phase.
- **D-08 (roles and verification):** executor commits per task with named files, one SUMMARY ≤60 lines; STOP and report on a bench regression above 10 percent on medians, a needed format change, or an oracle assertion change. Independent verifier (no CONTEXT/PLAN/SUMMARY) applies each recorded mutation in fresh scratch copies (own `CARGO_TARGET_DIR`), poisons a middle locator and a sealed-segment binding in a real Rocks dir, checks `verify_full()`, re-measures the allocation numbers with its own counting allocator, re-runs the bench pairs, checks the dead-code removals have no caller, and runs fmt/clippy/`cargo test --workspace --offline`/rocks feature tests/`kutha-gov py precommit ci selftest`/pytest.
