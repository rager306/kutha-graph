## Locked decisions

- **D-01 (no owner-gated behaviour):** nothing here decides C01, HORN-KC-01, ASOF-ELIG-01, DET-02, TR-02 or HORN-CORR-01. Tests that touch those areas are `characterization` (labelled per ADR-023 D023-2) or stay `blocked` rows. If a new oracle diverges because of an owner-gated rule, stop treating it as a bug: record it as a `blocked`/`characterization` row with the decision id and move on.
- **D-02 (determinism and tooling):** seeded hand-rolled LCG (the `m017_determinism.rs` pattern), no new dependency (no proptest/bolero), no wall clock, no sleep, no network. Failures print the seed, the case index and a prefix-shrunk minimal event list (simple shrinker: smallest prefix, then drop-one-event passes). Seeds: a fixed list of ≥ 64 seeds for the default run; env `KUTHA_SEEDS=<n>` may raise it (documented); total added test time under default settings ≤ 30 s on this host. EventIds are not stable (UUID v7): compare facts as (subject, relation, object, vt/tt stamps, claim identity class), never raw ids, unless a test builds the same events once and replays that list through every path.
- **D-03 (scope, ordered):** (1) `SEM-csr-fold-diff` / DIFF-01 + DIFF-02: seeded random logs (Assert, Retract, Correct, CorrectInterval, Behavior-free first, then with Horn rules) compared across fold `live_at`/`as_of`/`as_known_on`, the typed and untyped CSR leases at random (tt, vt) cuts, and a clean rebuild after `persist`+`open` (legacy layout, segmented layout with the rollover seam forcing several segments, and `migrate`); all agree. (2) NEW model-based oracle `SEM-bitemporal-model`: a deliberately naive reference implementation of the bitemporal semantics in test code (≤ 200 lines, written from ADR-013 and the FF5 fixture, independent of `fold.rs` internals: list scan, no indexes) compared with `GraphFold::live_at`/`as_of` over random logs and cuts. (3) `SEM-cascade-order`: stable cascade order and commit order across Eager vs Lazy index modes for rules with inverse relations (`knows`/`inverse_knows`), same derived triples in the same order; (4) NEW metamorphic oracles: `SEM-order-independence` (permuting independent facts that touch disjoint subjects does not change the final fold fingerprint on triples), `SEM-replay-idempotence` (replay of a log twice into fresh runtimes gives the same fingerprint; `replay_check` accepts), `SEM-persist-roundtrip-random` (persist→open equals the in-memory fold for legacy, segmented, migrated, and `export_jsonl`-imported layouts), `SEM-replay-tamper-random` (flip/swap/drop one event in a persisted log: open or `replay_check` fails closed or the fold differs and the test says which; never silently equal). (5) `SEM-horn-correct-char`: characterization of the current behaviour of `Correct`/`CorrectInterval` on a Horn premise (derived rows after the correction), labelled as characterization, with the decision id HORN-CORR-01 in the matrix. Reuse existing helpers; do not copy production logic into the reference model (the model must be able to disagree).
- **D-04 (bugs):** a divergence not explained by D-01 is a real finding. RED first: keep the failing seed as a named regression test (seed + minimal list), fix in `src/` with the smallest change, show GREEN. If the fix would change a named oracle assertion (FF5, FF6, M010–M017, `m002_*`, `m019_*`) or needs a decision, STOP and report (controller decides). Any `src/` change triggers the bench gate for that change (6 interleaved pairs, controller-style) and goes through CBM `trace_path` + GitNexus `impact` first.
- **D-05 (mutations):** for every new oracle, record at least one concrete mutation of production code that makes it fail, applied in a scratch copy with a fresh `CARGO_TARGET_DIR` (for example: CSR lease ignores the relation label; `live_at` ignores `tt`; `as_known_on` uses the wrong anchor; Retract applied before its target; cascade appends in reverse order; persist drops the last event of a segment; replay skips `Correct`). Weak oracles (the mutation survives) must be strengthened or demoted to `characterization` in the matrix.
- **D-06 (matrix and docs):** add rows for the new oracles to `docs/architecture/test-matrix.yaml` (statuses honest, `kill_mutation` filled, owners `M019-S07` or decision ids); update `.md` counts; the `test-matrix` governor check stays green. ADR-013/041/060 get one dated 2026-10-05 Evidence line each (what is now differentially/model tested; what stays open: Horn@TT=MAX, `as_of` vs eligibility, C01). CHANGELOG Product entry in the last commit. No ADR status change.
- **D-07 (roles and verification):** executor commits per task with named files, one SUMMARY ≤ 60 lines. Independent verifier (no CONTEXT/PLAN/SUMMARY) runs every recorded mutation, adds two of its own mutations per oracle family, checks the reference model for independence (no imports of fold internals; reads like the ADR), checks runtime budget and flakiness (20 runs of the default seeds), runs `KUTHA_SEEDS` at a higher value once, and the usual gates (fmt, clippy, `cargo test --workspace --offline`, rocks feature tests, `kutha-gov py precommit ci selftest`, pytest).
